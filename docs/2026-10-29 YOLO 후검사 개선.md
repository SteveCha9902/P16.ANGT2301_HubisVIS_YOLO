# P16 YOLO 후검사 개선 (2026-10-29)

P16은 `P15.ANGT2301_HubisVIS_Line`(HEAD `14c9e53` + 10-13 미커밋 변경 포함)을 복사한 프로젝트다. 목표는 코드에 일부만 구현되어 있던 YOLO 딥러닝 후검사(`DETECT_BLOB2`)를 실제로 동작하게 만드는 것이다.

복사할 때 제외한 것: `26.1014_borg`, `Borgwarner_Log`, `Deploy`, `*.zip`, `.vs`, `**/x64`, `bin/Log`.

## 기존 상태 (P15)

- `Config.ini [DeepLearning] AfterInspectionDL=1`이면 `DETECT_BLOB2` 판정이 `SetCriteriaBlob2` 대신 `SetCriteriaYOLO`로 바뀐다.
- YOLO 서버 호출(`SocketYOLO_SingleCall`)은 `DlgMain2::OnBnClickedBtnInspection`에만 있었고, 그마저 주석 처리되어 있었다. 자동·수동 검사 어느 쪽에서도 서버를 부르지 않았다.
- `SetCriteriaYOLO`는 `m_vecYOLOResultBox[idx]`를 측정점 인덱스로 바로 읽었다.
  - 박스가 측정점보다 적으면 범위를 넘어 읽어 크래시가 난다.
  - 박스 순서와 측정점 순서가 같다는 보장이 없어서 위치가 서로 다른 박스로 판정할 수 있다.
- 결과 벡터를 수신에 성공했을 때만 비웠다. 그래서 실패하면 이전 시료의 박스가 남았다. `m_vecYOLOSpatterBox`는 한 번도 비우지 않았다.
- 파서에서 `find`가 실패해도 검사하지 않았다. 그래서 깨진 응답이 오면 `substr`에서 `std::out_of_range`가 발생할 수 있었다.
- IP·포트·timeout·confidence가 하드코딩되어 있었고, connect에는 timeout이 없었다(원격 IP가 응답하지 않으면 약 21초 블록).

### 흐름

`DoInspectionBlob2Algo` → `DoCriteria` → `SetCriteriaYOLO`(DL 사용 시)

1. `RequestYOLO(itemIndex)`: `DoDetectBlob2`와 같은 원본 영상(`g_MemoryManager.GetByteImage(itemIndex)`)을 `<YOLOWorkPath>\yolo_t<thread>_item<item>.bmp`에 저장한다. 파일은 매 시료 덮어쓰므로 쌓이지 않는다.
2. `SocketYOLO_SingleCall`: 기존 프로토콜(ANSI 경로 + `\n` 전송 → JSON 한 줄 수신)을 유지한다. 바뀐 점은 다음과 같다.
   - connect는 non-blocking + `select`로 timeout을 건다.
   - 부분 send/recv를 처리하고, 응답은 최대 1 MB로 제한한다.
   - `"error"` 키가 있는 응답은 실패로 처리한다.
   - 매 호출마다 WSAStartup/WSACleanup을 한다(다른 모듈이 초기화했는지에 의존하지 않음).
3. `ParseYOLOResult`: `"class"` 키 단위로 항목을 잘라 읽는다. 형식이 깨진 항목은 건너뛰고 개수를 로그로 남긴다. `YOLOConfidence` 미만은 버린다.
4. 판정:
   - Blob2 측정점(`m_vecResult[idx].rtROI`, 전체 영상 좌표)마다, 겹침 비율(교집합 / 작은 쪽 면적)이 `YOLOMatchRatio` 이상인 미사용 welding 박스 가운데 가장 많이 겹치는 것을 고른다.
   - 고른 박스의 폭·높이 × 해상도로 기존 `fWeldWidth/HeightMin~Max` 기준을 적용한다.
   - 맞는 박스가 없으면 그 측정점은 NG(`ALARM_CRI_BLOB2`)다.
   - 판정에 쓴 YOLO 크기를 `m_vecResult`에 반영하므로 결과 화면과 CSV에도 같은 값이 나간다.
   - YOLO 호출이 실패하면 `YOLOFailFallback=1`(기본)일 때 기존 룰베이스 `SetCriteriaBlob2`로 판정하고, `0`이면 모든 측정점을 NG로 처리한다.

## 미검증·위험

- 실제 YOLO 서버(Python, 저장소에 없음)와의 연동, 실제 영상의 박스 좌표계(전체 영상 기준 가정)는 확인하지 않았다. 서버 응답 형식은 기존 파서가 가정하던 `"class"` → `"confidence"` → `[x1, y1, x2, y2]` 순서를 따른다고 보았다.
- 검사 스레드에서 BMP 저장(2448×2048 약 5 MB)과 YOLO 응답 대기만큼 사이클 시간이 늘어난다. 실제 소요 시간은 `[YOLO] Item n : ... save/total ms` 로그로 측정해야 한다.
- `YOLOMatchRatio`, `YOLOConfidence`, spatter 판정 기준은 실제 영상으로 튜닝해야 한다.
- 실장비·PLC·HIL 시험은 하지 않았다. Debug 빌드도 하지 않았다(Release와 출력 폴더가 같아서).
- `Inspection.cpp`의 기존 YOLO 주석 일부는 이전 인코딩 변환에서 이미 깨져 있었다(이번 교체 구간은 새 주석으로 대체).

## 2026-11-01 타원 라벨·회전 박스 판정

사용자 결정: 라벨을 타원으로 하고 모델이 타원 모양으로 검출하며, 크기는 **타원을 감싸는 회전 박스(타원 축 방향)**의 가로·세로로 구한다.

| 파일 | 내용 |
| --- | --- |
| `AlgorithmTools/Inspection.h` | `YOLOBox`에 `hasEllipse`, `ecx/ecy/ew/eh/eangle` 추가(기본값 초기화). 구조체 크기가 바뀌므로 AlgorithmTools·VisionMain을 함께 빌드해야 한다 |
| `AlgorithmTools/Inspection.cpp` | `ParseYOLOItem`: box 뒤의 선택 항목 `"ellipse": [cx, cy, w, h, angle]`을 읽는다. 없거나 깨졌거나 크기 0이면 `hasEllipse = FALSE` |
| `AlgorithmTools/DoCriteria.cpp` | `SetCriteriaYOLO`: 타원이 있으면 W = `ew`, H = `eh`를 축 방향 해상도로 mm 환산해 판정, 없으면 기존 박스 크기. NG 로그에 `ellipse/box`·각도 추가 |

- 축 규칙: `ew`는 영상 가로축에 가까운(±45°) 축, `eh`는 그 수직 축이다. 세로로 긴 비드에서도 W/H가 레시피 `fWeldWidth/Height`(가로/세로) 의미와 바뀌지 않게 하려는 규칙이다.
- mm 환산: W = `ew`·√((resX·cosθ)² + (resY·sinθ)²), H = `eh`·√((resX·sinθ)² + (resY·cosθ)²). X/Y 해상도가 같으면 기울기와 관계없이 `ew·res`, `eh·res`다.
- 측정점 매칭은 기존대로 축 정렬 `box`와 Blob2 ROI의 겹침 비율로 한다.
- 서버 응답에 `ellipse`가 없으면(검출 모델·mock) 기존과 같은 결과다.
