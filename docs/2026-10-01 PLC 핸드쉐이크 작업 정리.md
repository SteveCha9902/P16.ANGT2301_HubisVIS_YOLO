# 2026-10-01 PLC 핸드쉐이크 작업 정리

PLC 통신 중 시퀀스가 진행되지 않는 현상의 원인을 분석했습니다. 소스 코드는 변경하지 않았고, 빌드·실행·PLC 시험도 하지 않았습니다.

## 결과 요약

- 현장 로그 `Borgwarner_Log` 2026-08-24~27(53개 파일, 4,760 사이클) 기준으로 정상 4,758 사이클, 정지 2건입니다. 통신 timeout, 재접속, 스캔 실패는 0건입니다.
- 정지 2건(08-25 09:40 Seq 1579→1580, 08-26 10:49 Seq 1709→1710)은 같은 패턴입니다. `REQ_Insp_Move` 후 `RESP_Insp_Move`가 관측되지 않았고, 다음 사이클의 Move 요청에 PLC가 142초, 24.5초 동안 응답하지 않았으며, 이후 프로그램이 재시작됐습니다. OK/NG 판정과는 관계가 없습니다.
- Vision 측 주요 결함:
  - 비트 하나를 쓰면 같은 워드의 다른 비트가 0이 됩니다(`CtrlPLC.cpp:233`). 미응답 Move 요청이 다음 Start 응답 때 지워지고, LinkTest가 Ready/Initialize 응답을 지웁니다.
  - Move 요청에 timeout·알람·복구가 없습니다.
  - 검사 결과 기록이 Move 요청보다 늦습니다(4,756/4,760 사이클, 평균 +46 ms).
  - 그 밖에 Start 응답 50 ms 고정 펄스, 스캔 중 폴링 정지(약 1.1초), 통신 오류 시 재접속이 기존 소켓 재사용, 스캔 실패 통보 미도달, 초기화 중 폴링 지연.
- PLC가 첫 Move에 응답하지 않은 이유는 Vision 로그만으로는 확정할 수 없어 래더 확인이 필요합니다.

## 다음 행동

1. 질문지를 PLC 담당자에게 공유하고 회신을 받습니다. 우선 항목은 M1~M5(Move 조건), L1~L3(Ready·Initialize), R1(결과 읽기 시점)입니다.
2. 회신 내용으로 수정 방안의 결정 항목을 확정하고 적용 승인을 받습니다.
3. 첫 적용은 위험이 낮은 진단 로그(Move 미응답 경고, 워드 쓰기 전후 값)부터 진행합니다.
4. 비트 덮어쓰기 수정은 빌드와 오프라인 확인 뒤, 별도 승인을 받아 PLC 연동 시험을 합니다.

## 작업 환경 메모

- Git 저장소가 없습니다. 변경 전 기준선(Git 초기화 또는 폴더 백업)을 먼저 확보해야 합니다.
- 관련 소스 대부분(`CtrlPLC.cpp`, `PLCSocketManager.cpp`, `CtrlPLC_Melsec.cpp`, `PLCManager.cpp` 등)은 CP949입니다. 편집하는 파일만 UTF-8 with BOM으로 변환합니다. `CtrlPLC_Melsec.cpp`, `DataSaveManager.cpp`에는 이전부터 깨진 주석이 있습니다.
- 솔루션 `HubisVIS.sln`, v141, Windows SDK 10.0.17763.0, MFC Dynamic, 주 구성 Debug|x64. vcxproj에 `/utf-8` 옵션은 없습니다.
