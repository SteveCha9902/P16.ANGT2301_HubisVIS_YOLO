## 한눈에 보기

이틀 동안 P15 라인 비전 프로그램이 **장비를 멈추게 하던 원인들을 찾아 없앴고**, 카메라가 없어도 검사를 계속할 수 있게 만든 뒤 현장 배포 패키지까지 준비했습니다.

- **어제(10/14):** 카메라가 안 켜지던 문제의 원인(실행 폴더에 일부만 복사된 카메라 DLL)을 찾았습니다. 배포 패키지를 자동으로 만드는 도구를 만들었고, 검사 결과 이미지(JPG)가 저장되도록 고쳤습니다.
- **오늘 새벽 장애:** 03\~04시 화면이 멈춘 것처럼 보인 원인은 **Windows 업데이트 자동 재시작**이었습니다. 02:06 알람은 검사 1건이 실패했을 때 프로그램이 결과를 PLC에 보내지 않아 생겼습니다.
- **개선:** 설정값 `PLCAutoPass=1`일 때는 검사 실패, 카메라 고장, PLC 신호 이상이 생겨도 알람을 켜지 않고 다음 공정으로 넘어가도록 바꿨습니다. 카메라가 없으면 미리 넣어 둔 **Master 이미지**로 대신 검사합니다.
- **검증:** 실제 PLC 대신 시험용 가짜 PLC를 만들어 8가지 고장 상황을 일부러 일으켰습니다. 모두 **알람 0회**로 정상 진행했습니다.
- **배포:** 현장 적용 패키지를 만들었습니다. 적용 후 X를 눌러도 프로그램이 남아 있던 문제는 **10초 안에 반드시 종료**되도록 고쳤습니다.

## 배경: 비전 시스템은 어떻게 일하나

라인은 PLC(설비 제어 컴퓨터)와 비전 PC가 신호를 주고받으며 한 칸씩 진행합니다. 한 제품마다 이 사이클을 위치(Div)별로 반복합니다.

&#91;embedded content: P15 라인 비전 구성과 검사 한 사이클 · 6단계\]

PLC는 ⑤ 이동 요청을 받아야 다음 위치로 넘어갑니다. 비전이 이 신호를 보내지 못하거나 알람을 켜면 라인이 멈추므로, 이번 작업의 핵심은 어떤 상황에서도 ④·⑤를 제때 보내게 하는 것이었습니다.

## 오늘 새벽 장애 분석

새벽 장애는 서로 다른 두 사건이었습니다. 02:06 알람은 검사 실패 처리 문제, 03\~04시 멈춤은 Windows 업데이트 때문입니다.

&#91;embedded content: 현장 PC Windows 이벤트 로그(docs\\251015.evtx) · 비전 로그 Log\_20261015\_00\~04\]

- **03\~04시 멈춤:** Windows가 업데이트를 설치하면서 03:11, 04:03, 04:04에 PC를 스스로 재시작했습니다. 설정된 ‘사용 시간’이 08:00\~17:00이라 새벽은 재시작이 허용된 시간이었습니다. 블루스크린이나 비정상 종료 기록은 없었습니다.
- **02:06 알람:** 후검사 제품 1개에서 검사 영역 계산이 실패(`bot-top erorr`)했습니다. 프로그램은 실패한 카메라의 결과를 PLC에 보내지 않았고, 5초 기다린 뒤 알람을 켰습니다. PLC는 알람이 뜨면 프로그램을 재시작해야만 복구되므로 작업자가 재시작했습니다.
- **대책:** Windows 자동 재시작은 로그온 상태에서 막는 정책(`NoAutoRebootWithLoggedOnUsers=1`)을 안내했고, 알람 문제는 다음 장의 개선으로 고쳤습니다.

## 개선 1: 알람·멈춤 없이 계속 진행

현장은 검사 결과를 모두 OK로 보내는 `PLCAutoPass=1`로 운영 중입니다. 그런데도 아래 상황에서는 알람이 뜨거나 PLC가 끝없이 기다리며 라인이 멈췄습니다.

&#91;embedded content: 변경 전후 비교 · 상황 5종\]

변경 후에는 비전이 어떤 경우에도 판정 OK(1)과 이동 요청을 보내고, 로그에 `[Applying AutoPass]`를 남겨 어느 사이클이 예외 처리됐는지 나중에 찾을 수 있습니다. PLC가 이동 응답을 주지 않는 경우는 비전이 풀 수 없으므로, 알람 대신 오류 로그만 남기고 다음 시작 신호에서 자동으로 정리합니다.

## 개선 2: 카메라 없이도 검사하기 (Master 이미지)

`PLCAutoPass=1`일 때 카메라나 조명이 연결되지 않으면, 미리 넣어 둔 **Master 이미지**를 촬영 이미지 대신 써서 검사를 계속합니다.

- **이미지 위치:** 실행 폴더의 `Simulation\Before`(전검사)와 `Simulation\After`(후검사)에 각각 6장입니다. 카메라 2대 × 검사 위치(Div) 3곳입니다.
- **사용 시점:** 카메라·조명 미연결, 또는 촬영 시간 초과 때입니다. 카메라가 정상이면 지금과 똑같이 촬영합니다.
- **기록:** 대체할 때마다 로그에 `[MASTER_IMAGE]`가 남아, 어느 사이클이 대체됐는지 추적할 수 있습니다.

이 기능을 만드는 과정에서 숨어 있던 문제 2가지를 더 찾아 고쳤습니다.

| 문제 | 어떤 일이 생겨나 | 수정 후 |
| --- | --- | --- |
| 카메라 1대만 연결이 안 돼도 시작 초기화가 중단됨 | 두 번째 카메라·이미지 메모리가 준비되지 않아, 검사가 시작되면 프로그램이 멈추거나 죽을 수 있었음 | 로그만 남기고 초기화를 끝까지 진행 |
| 검사 결과가 비어 있으면 판정값(InspRet)을 쓰지 않음 | PLC가 판정값 0을 읽고 OK/NG를 기다리며 멈출 수 있었음 | 빈 결과도 OK(1)를 기록 |

지금 넣어 둔 Master 이미지는 시뮬레이션용 샘플입니다. 실제 라인의 양품 이미지로 바꾸는 것을 권장합니다.

## 배포와 종료(X) 문제 대응

최종 배포 패키지는 `Deploy\HubisVIS_20261015_1016.zip`입니다. 알람 예외처리, Master 이미지, 결과 JPG 저장, 종료 감시가 모두 들어 있습니다.

- **내용:** 실행 파일 3개(`HubisVIS.exe`, `VisionMain.dll`, `AlgorithmTools.dll`)와 도구 프로그램, Master 이미지 12장입니다. 시험에 쓴 파일과 똑같은지 확인했습니다.
- **현장 설정(Config)은 바꾸지 않습니다.** 현장 Config에 `PLCAutoPass=1`이 있어야 새 기능이 동작합니다.
- 처음 만든 패키지(`_1002`)는 종료 문제 수정 전 버전이라 `_1016`으로 대체합니다.

### X를 눌러도 종료되지 않던 문제

현장 적용 후 X를 눌러도 프로그램이 살아 있다는 보고가 있었습니다. 종료할 때 작업 스레드를 하나씩 정리하는데, 각각 최대 5초씩 기다려 최악의 경우 약 90초가 걸리고, 카메라 해제 단계에서 멈추면 영원히 남을 수 있는 구조였습니다.

- **수정:** 종료 확인에서 Yes를 누르면 ‘종료 감시’가 시작됩니다. 10초 안에 끝나지 않으면 `Log\ExitWatchdog.txt`에 기록을 남기고 강제로 종료합니다.
- **시험:** 정상 상황에서는 0.1초 만에 종료됐고 감시는 동작하지 않았습니다. 감시 시간을 1ms로 줄인 시험판에서는 강제 종료와 기록이 모두 확인됐습니다.
- **주의:** 강제 종료 직후에는 카메라가 아직 잡혀 있을 수 있어, **5초 이상 기다린 뒤** 다시 실행해야 합니다.

## 남은 과제와 현장 확인 목록

현장 적용 후 아래를 확인해 주세요.

- [ ] 현장 `Config\Config.ini`에 `PLCAutoPass=1`이 있는지 확인
- [ ] Windows 업데이트 자동 재시작 차단 설정 적용 (로그온 상태에서는 자동 재시작 안 함)
- [ ] 로그에서 `PLC_DO_ALARM ON`이 0건인지 확인
- [ ] 로그에 `[MASTER_IMAGE]`·`[CAMERA_DIAG]`가 나오면 카메라·조명 점검 (정상 운전 중에는 0건이어야 함)
- [ ] `Log\ExitWatchdog.txt`가 생기면 같은 시각 로그를 개발 담당에게 전달
- [ ] Master 이미지를 실제 라인 양품 이미지로 교체
- [ ] 외장 SSD(E:) 케이블 점검 (10/14 13:56 분리 기록)
- [ ] 소스 커밋 (배포 파일과 소스를 연결해 두기 위함)
- [ ] 검사 중간 실패 사이클도 결과 JPG를 남길지 결정

**알아 둘 점:** `PLCAutoPass=1`에서는 카메라가 고장나도 OK로 계속 진행합니다. 또 PLC가 응답하지 않는 상황은 더 이상 알람으로 알리지 않으므로, 로그와 화면 아이콘을 보고 알아차려야 합니다. 실제 카메라·PLC를 연결한 현장 시험은 아직 하지 않았습니다.

### 용어 풀이

| 용어 | 뜻 |
| --- | --- |
| PLC | 라인 설비를 제어하는 산업용 컴퓨터. 비전에 검사를 요청하고 결과를 받음 |
| PLCAutoPass | 비전 설정값. 1이면 검사 결과와 관계없이 PLC에 OK를 보냄 (현재 현장 운영 방식) |
| InspRet | 비전이 PLC에 쓰는 판정값. 1 = OK, 2 = NG |
| 이동 요청 (REQ\_Insp\_Move) | 비전이 “촬영·검사 끝, 다음 위치로 이동해도 됨”을 알리는 신호 |
| 알람 (PLC\_DO\_ALARM) | 비전이 이상을 알리는 신호. 켜지면 설비가 서고 프로그램을 재시작해야 복구됨 |
| Div | 한 제품에서 촬영하는 위치 번호 (0, 1, 2) |
| Master 이미지 | 카메라가 없을 때 대신 쓰는 미리 저장해 둔 촬영 이미지 |
| ERROR\_STEP | 검사 알고리즘이 중간에 실패했을 때 프로그램이 들어가는 단계 |
